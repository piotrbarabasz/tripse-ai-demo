## Reproduce and check

Use Python 3.12 with `requirements.txt` and `requirements-dev.txt` installed and
Node 24.18.0/npm 11 (`frontend/.nvmrc`). Tested Python patch: 3.12.5. Contract tools:
FastAPI 0.115.12, Pydantic 2.11.4, Hey API 0.99.0, TypeScript 6.0.3,
Zod 4.6.7 and TanStack React Query 5.105.0. Direct npm inputs are exact and locked.
Generator usage follows [Hey API's maintained documentation](https://heyapi.dev/docs/openapi/typescript/get-started);
query cancellation/cache behavior follows [TanStack QueryClient](https://tanstack.com/query/latest/docs/framework/react/reference/QueryClient).

From the repository root (activate the Python environment first):

```sh
python -m scripts.export_openapi
python -m scripts.export_api_fixtures
npm --prefix frontend ci
npm --prefix frontend run api:generate
python -m scripts.export_openapi --check
python -m scripts.export_api_fixtures --check
npm --prefix frontend run api:check
npm --prefix frontend run typecheck
npm --prefix frontend run lint
npm --prefix frontend test
npm --prefix frontend run build
python -m pytest -q
python -m scripts.gcp.ci offline
python scripts/dev.py test-browser
git diff --check
```

On Windows the existing interpreter is `.venv/Scripts/python.exe`; CI uses
`.venv/bin/python`. `api:generate` and `api:check` work independently of the caller's
directory. Run frontend unit tests from `frontend` (Vitest's configured root).

`export_openapi` clears inherited environment configuration **before importing**
`app.main`, explicitly selects local/mock and temporary SQLite/document/fixture
paths, supplies disabled WAHA settings and an unbuilt temporary frontend path.
It calls `app.openapi()` without entering lifespan, initializing stores, launching
a worker or contacting services. Environment is restored on exit. JSON uses sorted
keys, UTF-8, LF and no timestamps. Tests prohibit network connections/storage
initialization and prove fresh-import safety with hostile inherited cloud settings.
The module-level ASGI composition in `app.main` is preserved unchanged.

The wire-fixture exporter separately enters TestClient lifespan against temporary
data, makes synthetic API requests and normalizes only timestamps and random IDs.
It exercises Studio source/draft/library/history/conflict/preview/image paths and
Planner acceptance/status. It never starts a worker. `fixtures.json` is regression
evidence, not product demo data. Python checks current wire output against it;
Vitest validates it with generated and supplemental guards.

Hey API reads only the local JSON artifact. Its TypeScript and Zod plugins generate
`frontend/src/shared/api/generated/{types.gen.ts,zod.gen.ts,index.ts}`. Treat this
directory as generated and never edit it manually. Check mode generates in a
temporary directory and compares the entire file set and normalized text; it does
not overwrite committed files. The negative test changes temporary copies and adds
an unexpected file to demonstrate drift failures. Generation is not part of image
startup or the production Vite build; no runtime schema download is made.

Hey API supports the repository's TypeScript 6 peer version. openapi-typescript
7.13.0 declares TypeScript `^5.x`, so it was not installed using forced peer overrides.
The exact `js-yaml` 4.3.2 override fixes the generator's transitive YAML advisory
chain; remove it when upstream accepts a patched version and revalidate generation.
The pre-existing minimatch override remains.

provider credentials, identity assertions, production URLs or data-store contents
are injected into it. Internal cloud task execution is `include_in_schema=False`;
SPA/static serving is absent. The local-only WAHA operation and mock simulator
remain in the schema because they are existing local routes. They have no new
browser adapter and are not cloud API availability promises. Cloud and readonly

## Runtime and query conventions

Transport requires relative `/api/…` or `/health` URLs, same-origin credentials,
no-store requests, and redirect:error. It handles JSON with required decoder, HTML
and image/octet-stream blobs, JSON writes and raw byte writes. Success status and
headers are preserved. Missing/wrong MIME, invalid JSON, failed guards, redirects
and opaque responses are errors. Browser fetch may report a blocked redirect as a
network TypeError; it is never followed or interpreted as successful empty JSON.
Timeouts cover fetch **and body decoding**, default 5 seconds, allowed >0 to 60s.
Caller cancellation is forwarded; timers/listeners are cleaned up even on errors.

ApiError distinguishes 400/401/403/404/409/413/422/503, other HTTP, network, timeout,
cancellation and invalid responses. It contains safe fixed messages, status and
bounded validation field locations/machine codes. It drops server detail messages,
submitted input, ctx and raw bodies. Features can translate these safe categories
to Polish. No browser token/key storage or provider configuration is introduced.
`validation-runtime.ts` disables Zod JIT before schema construction, avoiding
dynamic-function probes under the existing strict CSP. Browser regression must
report zero violations; no unsafe-eval or policy relaxation is introduced. See
[Zod CSP guidance](https://zod.dev/compile?id=how-it-works).

The root QueryClientProvider owns an in-memory client. Keys start `private-api`,
then domain/resource/ID or filters. One client belongs to one same-origin app/session;
recreate/clear it on any future composition or identity switch. No persisted private
cache. Both reads and mutations default to zero retries. Mutations execute once,
including offline network failures, and are never automatically queued for replay.
No reads currently justify a retry exception. Window-focus/reconnect refetch is off.
401 errors on queries or mutations clear private caches and abort outstanding reads;
the factory accepts a session-failure callback for future login UX. 403 stays a
permission error; it is not treated as proof that the session expired.

Use `jobQuery(id, optionalPollingAbortSignal)` with useQuery. Query signals propagate
to transport; the optional signal stops explicit polling cancellation even between
reads. Poll every 1500ms only for queued/running, with no background interval.
Terminal status, error (including auth), last-observer unmount or explicit polling
abort stops network polling. Cancelling a job read is not cancelling the server job;
there is no invented cancellation endpoint. Use a fresh controller for a new intent.

`createTripMutation` requires local or cloud_demo composition. Local sends no key
and must never be replayed as an idempotent create. Cloud requires the caller's UUID
key, retained for the same user intent, including any explicitly chosen manual retry.
Do not infer this capability from health or let a background effect create jobs.

`saveDraftMutation` submits the last loaded revision, invalidates Studio reads on
success only, and surfaces 409 with no retry, revision replacement or optimistic
overwrite. Status/duplicate adapters require generated revision/operation payloads;
keep their operation UUID stable for one user intent. Future forms own editable
snapshots/dirty state independently of query results. Seed once from loaded data;
never bind background refetch directly over unsaved fields. useQuery's pending/error/
success states and mutation pending/error state drive future feature UI; do not turn
failures into `{}`. Existing health loading/error/timeout UI stays unchanged and
continues to use its established effect lifecycle with the shared transport.

## CI, provenance and rollback

The existing read-only PR `checks` job adds one offline schema/wire/client drift
step after npm ci. Branches, Actions SHAs, checkout options, Python/node setup,
permissions and delivery workflow are preserved. Existing exact command-list tests
now require the added step without dropping previous checks.

FRONT-001B source contract already allows `.ts`/`.tsx` under frontend/src plus exact
package/lock inputs. Generated types and guards therefore enter exact manifests and
Docker's COPY frontend/src. Negative provenance tests cover changes to generated
files, exclude docs/schema/generation tooling from runtime inputs, and retain
historical Python-only releases unchanged. No allowlist/version/recipe relaxation
is needed. Docker consumes committed generated code; it need not have Python/schema
or Node generation scripts in the frontend stage. CI proves correspondence first.

Rollback reverts this client/provider/health-transport integration and the associated
generation/CI/dependency/docs changes together. Existing backend/data/legacy fetch
flows require no rollback or restoration. No release promotion, IAM, WIF, Terraform,
GCP resources or hosting changed.
