## Organization Policy migration — operator verification

The operator reports completing this administrative procedure on 2026-10-28:

- Project-level `iam.managed.allowedPolicyMembers` remains enforced and
  restrictive, allowing the three `user:` identities listed above and organization
  principal set `//cloudresourcemanager.googleapis.com/organizations/1058695423722`.
- Inherited legacy `iam.allowedPolicyMemberDomains` was overridden with
  `allowAll: true` only at project level. The organization-level legacy policy
  was not changed. The modern managed constraint continues to restrict IAM members.
- The temporary organization grant `roles/orgpolicy.policyAdmin` was removed;
  existing organization administration permissions were preserved.

Rationale: allow the explicitly approved external Gmail identities through the
managed membership policy while removing the legacy project-level domain-policy
conflict. Legacy `allowAll` is not public service access: it removes that legacy
constraint's project restriction, while the managed constraint, service IAM, IAP
and application membership still apply. No `allUsers` or `allAuthenticatedUsers`
access grant follows from this override.

Organization Policy is a separate administrative dependency, not managed by the
checked Terraform code. Future external-member changes require review of the
managed allowlist, service-specific IAP bindings and application memberships.
OAuth consent/audience/test-user and programmatic-client settings, GitHub
Environment protections/variables and policy administration remain separate
operator configuration responsibilities; a successful release does not manage them.
